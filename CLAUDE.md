# jsondev

Personal site built with Rust (axum), minijinja templates, and markdown content files.

## Project layout

```
content/       markdown files (blog, notes, recipes) with YAML frontmatter
data/          JSON files consumed by the workouts page
templates/     minijinja HTML templates
static/        CSS, JS, images
src/           Rust source
  routes/      one file per section (blog, notes, recipes, workouts)
  content.rs   markdown parser (frontmatter + pulldown-cmark)
  state.rs     AppState (template env, dir paths)
```

## Data pipeline

Workout data in `data/*.json` is generated by the [`hz2/fitness`](https://github.com/hz2/fitness)
repo and pushed here automatically by CI.

```
hz2/fitness (GitHub Actions, daily 06:00 UTC)
  1. fetch running data from Strava API
  2. fetch lifting data from Google Sheets (optional)
  3. export ~20 JSON files to ./output/
  4. checkout hz2/jsondev via SITE_REPO_TOKEN
  5. cp output/*.json jsondev/data/
  6. commit "chore: update workout data" and push
```

The workflow file is at `hz2/fitness/.github/workflows/update-workouts.yml`.
A keepalive workflow runs monthly to prevent GitHub from disabling the schedule.

### Secrets required in hz2/fitness

| secret | purpose |
|---|---|
| `STRAVA_CLIENT_ID` | Strava app client id |
| `STRAVA_CLIENT_SECRET` | Strava app client secret |
| `STRAVA_REFRESH_TOKEN` | long-lived refresh token from OAuth flow |
| `GOOGLE_SHEETS_CREDENTIALS` | service account JSON (optional, for lifting data) |
| `GOOGLE_SHEET_ID` | spreadsheet id from URL (optional) |
| `GOOGLE_SHEET_RANGE` | sheet range like `Sheet1!A:Z` (optional) |
| `SITE_REPO_TOKEN` | GitHub PAT with `contents: write` on hz2/jsondev |

`SITE_REPO_TOKEN` is a fine-grained PAT scoped to `hz2/jsondev` with read/write
on Contents. Create it at github.com/settings/tokens and add it to the fitness
repo secrets.

## Content

Each section reads markdown files from `content/<section>/`. Frontmatter fields:

```yaml
---
title: "post title"
date: 2026-01-01      # used for sorting
description: "..."    # optional, shown in list views
tags: ["foo", "bar"]  # optional
---
```

`_index.md` files are skipped by the loader.

## Running locally

```bash
cargo run          # http://localhost:3000
cargo test         # unit + integration tests
```

## Docker / VPS deploy

The Dockerfile bakes in `content/`, `templates/`, and `static/`. To deploy:

```bash
docker build -t jsondev .
docker run -d --restart unless-stopped -p 3000:3000 jsondev
```

`docker-compose.yml` mounts those directories as volumes for live-reload during
local development.
